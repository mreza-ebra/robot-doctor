A real TurtleBot3 standalone launch issue

TurtleBot3 · Public launch issue · Reviewed local correction

The state-publisher launcher reads namespace without a local declaration or default. The reported direct launch fails unless an external caller supplies that value.

Read upstream issue #1149 · Inspect the pinned source · Existing upstream proposed fix #1150

TurtleBot3 is ROBOTIS's mobile-robot platform. At capture its public repository had 2,078 stars and 1,188 forks. These are public interest signals, not clone counts or customer validation.

The reviewed local correction

turtlebot3_bringup/launch/turtlebot3_state_publisher.launch.py

- namespace = LaunchConfiguration('namespace')
+ namespace = LaunchConfiguration('namespace', default='')

+ DeclareLaunchArgument(
+     'namespace',
+     default_value='',
+     description='Robot namespace'),

The empty default permits an omitted namespace, and the declaration exposes it as a launch argument. The substitution still uses the name namespace so a caller can provide a value such as tb1. This is a local reproduction of the already proposed upstream approach.

How the analyzer improved for this case

The original detector at 48cb3c1 missed this condition. The generic RD304 check recognizes imported Python LaunchConfiguration calls with literal names, without executing them. Declarations, local assignments through SetLaunchConfiguration, and substitution defaults prevent a finding; dynamic or shadowed APIs are handled conservatively. No TurtleBot3 names were added to detector rules. This is an issue-guided reproduction, not blind discovery.
